= Diagrams as code
include::_fpsot-terms.adoc[]

These rules cover the source of each diagram in an {abbr-fpsot-first} repository.
Requirement DOC-030 of the documentation specification requires each diagram as code.
These rules say which code, where it lives and what it holds.

== Source

[[DIA-001]]
*DIA-001.* Authors MUST write the source of each diagram in link:https://plantuml.com/[PlantUML].
A diagram MUST NOT exist only as an image or as the file of a drawing tool.
PlantUML is open source, works offline and has a text syntax for each notation in this specification.
One language for every diagram lets each reviewer read and change any source.

[[DIA-002]]
*DIA-002.* Each diagram MUST have its own source file directly in the `diagrams/` folder at the repository root.
It MUST NOT sit in a subfolder.
Its `@startuml` line MUST name the diagram with the base name of its file, such as `@startuml registry-context-en`.
The shared diagrams workflow renders every `.puml` file of that folder.
The page build publishes the rendered files of that folder only, not of its subfolders.

[[DIA-003]]
*DIA-003.* A source written by hand MUST start with two comments, right after its `@startuml` line.
The first MUST give its license as `SPDX-License-Identifier: Community-Spec-1.0`, or the license of the repository.
The second MUST say what the diagram shows, and name the page or the requirement IDs it illustrates.
Readers then know the terms of reuse and where the diagram belongs.
A file that a generator writes, as DIA-018 sets, is exempt from DIA-002, DIA-003 and DIA-006.
The wrapper source that includes it MUST meet those three rules.

[[DIA-004]]
*DIA-004.* A source MUST render with the PlantUML version that the shared diagrams workflow pins, with its Smetana layout.
It MUST NOT need Graphviz or any other program.
It MUST NOT include a file from the network.
It MAY include the PlantUML standard library, such as `<C4/C4_Container>`, and files from `diagrams/`.
Every machine then draws the same image from the same source.
A file from the network could change or vanish without a {term-commit}.

== Content

[[DIA-005]]
*DIA-005.* A diagram SHOULD show one idea, with about twenty elements or fewer.
A larger subject SHOULD be split into several diagrams, such as one container diagram per system.
A small diagram stays readable on a phone, and its text alternative stays short.

[[DIA-006]]
*DIA-006.* Each diagram MUST have a `title` with its kind and its subject, such as "Container diagram of the registry".
It MUST have a legend for each shape, line style or color that its notation does not define.
A diagram then makes sense on its own, without the page around it.

[[DIA-007]]
*DIA-007.* Labels in a diagram MUST use the terms of the writing term base.
Its legend or its long description MUST spell out each abbreviation in the diagram.
A word in a diagram then means the same as in the text around it.
